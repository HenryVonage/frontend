How this demo is built

A high-level look at the integrations and moving parts behind each demo in this portfolio — useful if you want to build your own.

Architecture

Solid arrows: request flow. Dashed: Claude's response returned to the server (text flow) or streamed in real time alongside ElevenLabs (voice flow).

Prerequisites to build a demo like this

Vonage Application
Voice + Messages capable, with a private key for JWT auth, Answer/Event URLs pointed at your server.
WABA number
A WhatsApp Business number linked to the Vonage Application, with Cloud API Calling enabled for voice.
Approved message templates
Utility-category templates for anything sent outside the 24h session window (welcome, confirmations, call recap).
Node.js server (Render)
Express for HTTP webhooks, a raw websocket upgrade for real-time audio, secrets kept in env vars / Secret Files, never in the repo.
GitHub repo
Source of truth; Render auto-deploys on push. This static frontend is hosted separately on GitHub Pages.
Claude (Anthropic API)
Decides conversation steps for text chat, and acts as the reasoning LLM inside the ElevenLabs voice agent.
ElevenLabs Conversational AI
Handles speech-to-text, text-to-speech and turn-taking for voice calls, bridged to the caller over a websocket.

How a call/message flows end to end

  1. Landing page: visitor enters their name, picks a demo, and scans a QR code (or taps a link) encoding a pre-filled WhatsApp message to that demo's WABA number.
  2. Text flow: the message hits the server's webhook, Claude decides which step of the conversation it is, and the server sends back the matching WhatsApp template or free-form reply via the Messages API.
  3. Voice flow: if the visitor calls instead, Vonage's Answer URL returns an NCCO that connects the call to the server over a websocket; audio is bridged to an ElevenLabs agent (running Claude as its LLM) in real time.
  4. Call ends: the server fetches the call transcript from ElevenLabs, has Claude generate a short recap, renders it as a PDF, and sends it back over WhatsApp as an approved template (works even without an open session window).
  5. Delivery receipts: Vonage posts async status callbacks so the server can log/detect failures (e.g. unapproved templates, expired sessions).

Modeled loosely on Vonage's own "Build a 5-node AI WhatsApp receptionist" walkthrough — this version replaces the n8n workflow with a small Node.js server on Render.
